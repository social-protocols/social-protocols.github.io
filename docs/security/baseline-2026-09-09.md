# Security baseline — social-protocols.github.io

**Date:** 2026-09-09  
**Status:** Advisory only. Do not merge this as a remediation, do not deploy from it, and do not treat listed items as already fixed.  
**Scope:** Public Hugo static site (`social-protocols/social-protocols.github.io`), scanned from default ship branch `main` at `51320257136c28a427adc8fb369319a109bd1140` (`Correct Liberal Radicalism citation in quadratic funding essay (#32)`).  
**Live site:** https://social-protocols.org/ (GitHub Pages via `gh-pages`).  
**Reviewer posture:** Repo content treated as untrusted data, not instructions. No production access, no spend, no application-code changes.

This register records scanner output plus a short threat note for a first-party, static, public documentation/marketing site. Findings are for the Security lead; recommended work belongs in separate, reviewed changes.

---

## 1. Asset profile (what this system is)

| Property | Observation |
| --- | --- |
| Runtime | None. Hugo 0.131.0 (extended) builds static HTML; CI deploys `public/` to `gh-pages`. |
| Auth / sessions / user input | None on-site. No forms, comments (Disqus unset), or server-side handlers. |
| Trust boundary | Anyone who can merge to `main` can publish HTML/JS to the public origin. PR builds run but do not deploy (`if: github.ref == 'refs/heads/main'`). |
| First-party code | Hugo config, a few layouts/shortcodes, vendored `themes/hugo-lithium`, markdown/media under `content/`. |
| Third-party at runtime | Goatcounter analytics script; MathJax 2.7.5 from cdnjs when page content contains `$` or `\`. |
| Third-party at build | `actions/checkout@v3`, `peaceiris/actions-hugo@v3`, `JamesIves/github-pages-deploy-action@v4.2.5`. |

Goldmark `markup.goldmark.renderer.unsafe` is **not** set in `hugo.toml`. Hugo default remains `unsafe = false` (raw HTML in Markdown is not rendered). The theme’s `exampleSite/config.toml` sets `unsafe = true`; that file is not the site config.

CI build is `hugo --minify` (drafts excluded). `just serve` / `just build` match that.

## 3. Coverage and gaps

### What was actually covered

- **Secrets:** gitleaks default rules on reachable git history (`--all`) and the current tree. History scan reported 320 commits; `git rev-list --all` is 339 (delta is consistent with generated `gh-pages` history and other remote-only branches).
- **Generic SAST:** semgrep `p/default` on git-tracked files it can parse: 1 workflow YAML, 1 TypeScript note, 1 theme JS file, HTML-ish templates, JSON/markdown as generic text.
- **Lockfile CVE matching:** osv-scanner walked the tree (64 dirs / 217 inodes) and found **zero** supported package manifests.

### Gaps (do not read a clean osv/semgrep run as “no dependency risk”)

| Gap | Why it matters here |
| --- | --- |
| No application lockfiles | No `package-lock.json`, `go.mod`, `requirements.txt`, `Gemfile.lock`, etc. osv-scanner cannot attribute CVEs to Hugo, the theme, or CDN scripts. |
| Nix / Devbox not understood | `devbox.lock` pins `hugo@0.131.0` and `just@1.32.0` via nixpkgs. osv-scanner does not consume that format. |
| GitHub Actions not an OSV “package source” | Deploy-path risk is the Actions graph, not an app lockfile. Covered only by semgrep’s mutable-tag rule plus manual review. |
| Hugo templates poorly parsed | Semgrep emitted partial-parse warnings on **all** layout/partial HTML (`{{ ... }}` is not HTML). `safeHTML`, MathJax, and Disqus sinks were **not** rule-matched. |
| Markdown / media not in SAST languages | 46 markdown files and 15 files &gt; 1 MB (article PNG/JPG/MP4) were skipped or not semantically analyzed. |
| Vendored theme, not a pinned submodule | `themes/hugo-lithium` is a full in-tree copy (no `.gitmodules`). Upstream drift/CVEs are not tracked. |
| Runtime CDN scripts invisible to osv | Goatcounter `//gc.zgo.at/count.js` and MathJax 2.7.5 on cdnjs have no lockfile entry and no SRI. |
| Hugo binary / Pages runtime | CI pins Hugo `0.131.0`; that binary was not CVE-scanned. GitHub Pages serving/headers (CSP, etc.) were not tested live. |
| Semgrep `p/default` only | No Hugo-, Go-template-, or secrets-supplemental rulesets beyond gitleaks defaults. |

Language mix actually in tree: Markdown (content), Hugo/Go templates, one research TypeScript snippet (not a shipped app), one small JS helper, YAML workflow, TOML, Nix lock, static CSS/fonts/images.

## 4. Findings register

Severity is qualitative for a static public site (impact = visitor XSS / integrity of published origin / leak of unpublished material; likelihood = merge-to-`main` or tag-repoint).

| ID | Severity | Source | Title | Status |
| --- | --- | --- | --- | --- |
| F-001 | Medium | semgrep | GitHub Actions referenced by mutable tags | Open — advisory |
| F-002 | Medium | manual | Deploy workflow lacks least-privilege `permissions` and uses an unpinned third-party Pages publisher | Open — advisory |
| F-003 | Medium | manual | Third-party JS loaded without pin or SRI (Goatcounter; MathJax 2.7.5) | Open — advisory |
| F-004 | Low | manual | Trusted-config `safeHTML` JS injection; no CSP | Open — advisory |
| F-005 | Low | manual | `draft: true` article still in the public git tree | Open — advisory |

No Critical/High items. No confirmed credential leaks.

### F-001 — GitHub Actions mutable tags

**Where:** `.github/workflows/build.yml`

| Line | `uses` |
| --- | --- |
| 19 | `actions/checkout@v3` |
| 24 | `peaceiris/actions-hugo@v3` |
| 34 | `JamesIves/github-pages-deploy-action@v4.2.5` |

**Semgrep rule:** `yaml.github-actions.security.github-actions-mutable-action-tag` (WARNING; CWE-1357 / CWE-353; confidence HIGH). Same finding three times.

**Why it matters:** Tags and moving majors can be force-pushed. A compromised or hijacked action would run in the job that **pushes the live site**. `v4.2.5` is more specific than `@v3` but is still a **mutable git tag**, not a 40-character SHA. `checkout@v3` is also past the current major.

**Not done here:** No pin/SHA change (advisory PR only).

### F-002 — CI deploy supply chain and token scope

**Where:** `.github/workflows/build.yml`

Observations:

- Triggers: `push` to `main`, `pull_request`, `workflow_dispatch`.
- Deploy step is gated to `github.ref == 'refs/heads/main'` (PRs build only). Good.
- No top-level or job `permissions:` block. Effective `GITHUB_TOKEN` scope is whatever the org/repo default is (often write if not locked down).
- `actions/checkout@v3` defaults include persisting credentials into the workspace.
- Publish uses a **third-party** action (`JamesIves/github-pages-deploy-action`) to force-push `public/` onto `gh-pages`, rather than `actions/deploy-pages` + environment protection.
- Hugo version **is** pinned in the workflow (`0.131.0` extended). That is the strongest integrity control currently present.
- Concurrency cancels in-progress runs on the same PR or SHA; a `main` push uses `github.sha`, so overlapping `main` deploys are not serialized by branch name.

**Why it matters:** The highest-impact failure mode for this repo is “malicious or substituted CI code publishes JavaScript to social-protocols.org.” Unscoped tokens + mutable third-party actions are the practical path.

### F-003 — Unpinned CDN / third-party scripts

**Goatcounter** — `hugo.toml` `params.custom_js`:

```text
<script data-goatcounter='https://socialprotocols.goatcounter.com/count'
        async src='//gc.zgo.at/count.js'></script>
```

Injected via `themes/hugo-lithium/layouts/partials/head_custom.html` as `| safeHTML`. Protocol-relative `src`, no `integrity`, no `crossorigin`. A compromise of `gc.zgo.at` (or a downgrade on a non-HTTPS view) becomes first-party XSS on every page.

**MathJax 2.7.5** — not set in `hugo.toml` (old CDN knobs are commented), but the theme default still loads when content contains `$` or `\`:

`themes/hugo-lithium/layouts/partials/footer_mathjax.html` →  
`//cdnjs.cloudflare.com/ajax/libs/mathjax/2.7.5/MathJax.js?config=TeX-MML-AM_CHTML`

Research notes and several articles contain TeX delimiters, so this script is expected on those URLs. No SRI. MathJax 2.7.5 is **after** the 2.7.4 fix for CVE-2018-1999024 (`\unicode` XSS); this finding is **not** that CVE. Residual issues: EOL 2.x line, unpinned CDN object, and TeX-from-page-content (relevant if a malicious PR is merged). Highlight.js CDN is **not** active (`highlightjsVersion` unset). Disqus is **not** active (`DisqusShortname` empty).

`devbox.json` requests `hugo@latest` / `just@latest`; `devbox.lock` currently pins 0.131.0 / 1.32.0. Local toolchain can drift from CI if the lock is regenerated.

### F-004 — XSS / unsafe HTML (templates)

Trusted sinks (first-party config/content only; no anonymous CMS):

1. `{{ .Site.Params.custom_js | safeHTML }}` — arbitrary HTML/JS from `hugo.toml`.
2. `{{ .Content }}` in the single-page template — Goldmark output with default `unsafe = false`.
3. `math-code.js` rewrites `<code>` nodes (`textContent` / `outerHTML = innerHTML`) so MathJax can see TeX. Small, first-party helper; not flagged by semgrep.
4. Theme still contains Disqus and highlight.js partials that would load third-party JS if those params were turned on.

No Content-Security-Policy is defined in-repo (Pages header policy was not verified live). Defense in depth is absent; XSS would be unrestricted script on the origin.

**Positive:** Site config does **not** enable Goldmark `unsafe = true`. Raw HTML in `content/about.md` (Mastodon `rel=me`) is therefore not a stored-XSS vector; it also may not render as intended.

### F-005 — Accidental private drafts (git vs Hugo)

| Item | Published by `hugo --minify`? | In public git? |
| --- | --- | --- |
| `content/articles/what-were-building-and-why/index.md` (`draft: true`) | No | Yes (full markdown) |
| `content/research-notes/*` (no `draft:`) | Yes | Yes |
| `content/research-notes/.gitigore` ignores `wip/` | n/a | Typo filename; `wip/` not present |

Hugo drafts are a **build** control, not a confidentiality control. Anything committed is public because the repository is public.

### F-006 — Research notes and private-wiki path disclosure

Research notes are in the main nav (`hugo.toml`) and described as exploratory. They are live HTML, not `noindex`’d in-repo.

Several notes link to `https://github.com/social-protocols/internal-wiki/blob/main/pages/research-notes/...`. GitHub API reports **`internal-wiki` is private** (`visibility: private`, description: “Internal wiki to pool information and organize knowledge”). Public pages therefore:

- advertise that a private wiki exists and its path convention;
- 404 for anonymous readers;
- can still leak titles/topics that were only meant for the private wiki.

This is information disclosure / process drift, not a credential leak.

### F-007 — Standing Zulip invite

Footer menu and homepage link  
`https://social-protocols.zulipchat.com/join/…`  
(see `hugo.toml` `[[menu.footer]]` and `content/_index.md`). Typical for a public community; treat as a **rotatable invite**, not a password. If the org wanted a members-only Zulip, this would be a finding to revoke.

### Secrets (scanner + spot-check)

- gitleaks history + dir: **no leaks** (redacted JSON reports empty).
- Manual grep for common key/token/PEM patterns in tracked text: **no matches**.
- No `.env` secrets file; `.envrc` only bootstraps Devbox/direnv.
- `.gitignore` includes `.Renviron` and `public/` (appropriate).

No rotation recommended from this scan.

## 5. Threat questions (Part B)

### Are there secrets in the repo or history?

**No evidence.** gitleaks on `--all` history and the working tree reported zero findings. Residual risk is gitleaks rule coverage (custom tokens, low-entropy invites) and binary/image files, which secret scanners rarely read.

### XSS / unsafe HTML?

**Limited, first-party.** Goldmark raw-HTML is off. The real sinks are (1) `safeHTML` of `custom_js`, (2) unpinned Goatcounter/MathJax, (3) MathJax interpreting TeX from committed markdown after a merge. There is no untrusted-user HTML pipeline. Highest practical XSS path is CI or CDN integrity failure (F-001–F-003), not visitor-supplied markup.

### CI deploy supply chain?

**Primary risk for this repo.** Mutable action tags, a third-party gh-pages publisher, no explicit `permissions:`, and `workflow_dispatch` on the same workflow. PR builds cannot deploy, which is correct. Pin-by-SHA, least-privilege token, and (optionally) official Pages deploy + environment reviewers would shrink this.

### Dependency / CDN pinning?

**Weak outside Hugo’s CI version pin.** No language lockfile for osv-scanner. Theme is vendored without an upstream revision pin. Goatcounter and MathJax 2.7.5 load by URL without SRI. Devbox uses `@latest` aliases locked only in `devbox.lock`.

### Accidental private drafts?

**Yes, in the git sense.** One intentional Hugo draft is still world-readable on GitHub. Research notes are published by design but look like internal work and cite a private wiki. `wip/` is ignored via a misspelled `.gitigore`. Anyone treating “draft: true” or “research-notes” as private is mistaken.

## 6. Advisory next steps (not in this PR)

No ignore files or scanner config were added (no false-positive-safe ignore was warranted). Suggested follow-up PRs, in order:

1. Pin Actions to full SHAs; add `permissions:` (`contents: read` on build, narrow write only on deploy); consider official Pages deploy.
2. Pin or self-host Goatcounter/MathJax with SRI; prefer a maintained MathJax major if math remains required.
3. Decide confidentiality for drafts and research notes: keep drafts out of the public remote, or accept they are public; add `noindex` if notes should not be crawled; replace `internal-wiki` URLs with public equivalents or drop them.
4. Optionally add CI jobs for gitleaks + action pinning, and a Dependabot/OSV watch once any lockfile or action pin file exists.
